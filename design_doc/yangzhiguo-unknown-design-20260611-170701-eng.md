## 一、架构(Architecture)

### 1.1 关键设计原则(对工程偏好)

- **Boring by default:** 用 Kotlin + Jetpack Compose + Room + Retrofit + 微信支付 SDK。**不引入**新的 ML 框架、不自训模型、不上 KMM/HMP。
- **Incremental over revolutionary:** Week 1-2 先跑通"拍照 → 上传 → 你在微信里手答 → 用户看结论"。后端、推送、统计都是后加的。
- **Blameless failure:** 关键路径有 30 分钟 SLA 兜底,**业务失败靠流程而非技术补救**(你人在)。
- **Reversibility:** 价格、付费文案、AI API 选型都是可换的,别写死。

### 1.3 重要简化:**MVP 阶段可无后端**

你初期 1 个专家 × 30 分钟 SLA,直接用现成工具接单就行:

| 组件 | MVP(Week 1-4) | 跑通后(Week 5+) |
|---|---|---|
| 订单管理 | **微信群 / 微信群机器人 / 飞书多维表** | 后端 MySQL |
| 图片存储 | **你群里直接接收** | 阿里云 OSS |
| 推送 | **微信消息 / 短信 / 邮件** | App 推送(WebSocket/极光) |
| 支付 | **微信支付 SDK 直连**(不需要后端中转) | 同 |
| 后端 | **不需要** | 阿里云函数计算 + MySQL |
| 监控 | **飞书表格手工记录** | 友盟/自建埋点 |

**这是关键决策:Week 1-4 完全不需要后端。** 你的工作量变成"App + 微信支付 + 微信群接单"。后端是 50 个付费用户之后才上的事。

#### 流程 C: 100 种本地匹配(纯本地,无网络)

```
用户提交的特征:
  菌盖颜色=白, 菌褶=密, 菌环=有, 菌托=有, 栖息地=针叶林
       │
       ▼
┌─────────────────────────────────────┐
│  MatchLocalSpeciesUseCase           │
│  for each species in 100:           │
│    score = 0                        │
│    if (species.颜色 == 白) score++  │
│    if (species.菌褶 == 密) score++  │
│    if (species.菌环 == 有) score++  │
│    if (species.菌托 == 有) score++  │
│    if (species.栖息地 == 针叶林)     │
│        score += 2  # 重要特征加权   │
│  return top-3 by score              │
└─────────────────────────────────────┘
       │
       ▼
返回: [致命白毒伞(score=6), 白毒伞(score=5), ...]
```

**这是 MVP 阶段够用的"AI 预筛"。** 不用调任何外部 API,纯字符串匹配 + 权重。

### 1.6 关键非功能性需求

| 维度 | 目标 | 实现 |
|---|---|---|
| 离线可用 | 山上无信号时能浏览 100 种图鉴 | Room + 应用启动时拷贝 seed JSON 到数据库 |
| 拍照质量 | 1080p JPEG,≤2MB | CameraX 默认 + 上传前压缩到 800x800 |
| 上传速度 | 4G 下 ≤5 秒 | 图片压缩 + HTTP/2 + 阿里云 OSS 直传 |
| 30 分钟 SLA | 你 30 分钟内回复 | 推送 + 微信模板消息双重触发,App 端倒计时 |
| 错误兜底 | 任何技术错误不能让用户"白拍" | 拍照先存本地,上传失败可重试 |
| 安全 | 不主动说"绝对可食",用"概率 + 风险" | 结论文案模板 + 免责声明 |
| 隐私 | 蘑菇照片不公开 | 默认私密,只有你(和后续专家)能看 |

### 1.7 不在架构范围内(明确)

- ❌ 3D 模型(Phase 1 不做,2D 照片和 3D 对齐基本不 work)
- ❌ 多专家市场(招第二个专家是 30+ 付费用户后)
- ❌ 社区/UGC/评论
- ❌ 电商 / 采摘旅游合作
- ❌ AI 自动结论(只做"给你看"的预筛)
- ❌ iOS(用户决定 Native Android)
- ❌ 国际化(中文 only)
- ❌ 离线模式下的订单提交(没信号时只能浏览图鉴,不能下新单)

## 二、数据准备清单(按优先级)

### 阶段 0 — 写代码之前(Week 0)

#### D1. 100 种常见蘑菇离线图鉴 ⭐ **最高优先级**

| 字段 | 详情 |
|---|---|
| 数量 | 100 种(覆盖群里 80%+ 提问) |
| 字段 | 学名、中文名、属、毒性等级(0/1/2/3)、可食性、菌盖/菌褶/菌柄/菌环/菌托/栖息地/季节/常见地区、辨识要点、3-5 张图片 URL |
| 选种原则 | 你群里**最近 3 个月**被问到的前 100 种;参考 iflora.cn 的"常见蘑菇"列表;**必含**至少 5 种剧毒(致命白毒伞/毒鹅膏/红网牛肝菌/赭红拟口蘑/亚稀褶红菇) |
| 来源 | iflora.cn(手动选,不要爬)、中国蘑菇志、蘑菇识别 Mushby 公开图鉴(只看不存)、**你自己采的 / 群里历史照片** |
| 格式 | JSON 数组,字段如上,后转 Room schema |
| 估计工作量 | 10-20 小时(手动,无法自动化) |
| 风险 | 标注错误 → 用户误食。**必过你的眼睛,不让 AI 标注。** |
| 落盘 | `app/src/main/assets/species_seed.json`,App 首次启动时导入 Room |

#### D2. 100 种蘑菇的 3-5 张图/种 ⭐ **最高优先级**

| 字段 | 详情 |
|---|---|
| 数量 | 100 种 × 3-5 张 = 300-500 张图 |
| 角度 | 菌盖正面、菌褶底面、菌柄、菌环、菌托、生长环境、剖面 |
| 来源(优先级排序) | (1) 你自拍; (2) 群里历史照片(经发图人同意); (3) iflora.cn 公版; (4) Mushby 公开图鉴(只看不存,避免版权) |
| 格式 | JPEG,1080x1080 起步,<500KB |
| 估计工作量 | 20-30 小时(含整理、裁剪、命名) |
| 存储 | 阿里云 OSS(需先开通 D5),URL 写进 D1 的 species_seed.json |
| 版权 | 自拍/原创图无问题;他图需 CC 协议或作者授权;**不要**直接复制 Mushby/形色/花伴侣图 |

#### D3. 蘑菇特征关键词词表

| 字段 | 详情 |
|---|---|
| 菌盖形状 | 凸/平/漏斗/钟形/半球形/不规则 |
| 菌盖颜色 | 白/黄/红/褐/黑/紫/橙/绿/多色(枚举) |
| 菌褶 | 密/疏/无/弯生/直生/离生/延生 |
| 菌环 | 有/无/活动/易脱落 |
| 菌托 | 有/无/杯状/袋状/颗粒状 |
| 菌柄 | 中生/偏生/侧生/无柄 |
| 栖息地 | 针叶林/阔叶林/混交林/草地/田边/腐木/粪堆 |
| 季节 | 春/夏/秋/冬(中国主要采菇季 6-10 月) |
| 估计工作量 | 3-5 小时(基于你的经验) |
| 落盘 | `app/src/main/assets/feature_taxonomy.json`,用于 D1 的特征匹配 |
| 重要 | 命名要简单,普通人能选,不要用学术术语 |
