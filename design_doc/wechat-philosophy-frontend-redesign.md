# Mushroom App 前端重构设计文档

> 设计方向：以张小龙的产品哲学为启发，打造克制、自然、可靠的蘑菇识别工具  
> 状态：待确认  
> 日期：2026-06-12  
> 本轮范围：仅设计，不修改前端代码

---

## 1. 设计结论

Mushroom 不应该像一个陈列功能的“蘑菇门户”，而应该像一件安静、可靠、随手可用的野外工具。

用户打开 App 时，最常见的真实意图只有两个：

1. 我现在看到一株蘑菇，想立即识别。
2. 我想查一种蘑菇，了解它的特征与风险。

因此，重构后的产品只保留两条清晰主线：

- **识别**：打开 App → 拍照 → 确认照片 → 查看结论。
- **查阅**：进入图鉴 → 搜索或筛选 → 查看详情。

收藏、设置、关于等低频功能继续保留，但不与主任务争夺注意力。

一句话设计目标：

> **打开就知道该做什么，完成后可以放心离开。**

## 2. 哲学来源与转译

本方案不是复刻微信视觉，而是将其产品观转译为适合 Mushroom 的交互原则。

### 2.1 一切以用户价值为依归

转译：

- 首屏优先解决“我现在要识别”。
- 不为了展示数据库数量、AI 能力或功能丰富度而增加模块。
- 每个页面只回答用户当下最重要的一个问题。

### 2.2 好的产品，用完即走

转译：

- 从打开 App 到启动相机只需一次点击。
- 从拍照确认到识别结果不插入无必要表单。
- 结果页提供明确结论、风险提示和下一步，完成后不诱导继续浏览。
- 不用签到、连续使用、推荐流或伪通知制造停留。

### 2.3 触手可及

转译：

- 拍照按钮位于单手拇指舒适区。
- 相册作为相机页的自然次级入口，不藏在菜单里。
- 图鉴搜索框进入页面即可使用。
- 关键操作触控区域不小于 48dp。

### 2.4 克制不是少做，而是只留下合理的东西

转译：

- 一个页面只设置一个高强调主操作。
- 不使用大面积品牌色顶栏、彩色卡片堆叠和无意义装饰。
- 颜色主要传达操作和风险，不承担“让页面热闹”的任务。
- 内容有层级，但不过度卡片化。

### 2.5 把用户当朋友，而不是流量

转译：

- 不夸大 AI 识别准确率。
- 不用“可食用”作为鼓励采食的结论。
- 不展示模型原始思考过程，改为可核验的“识别依据”。
- 对不确定结果直接说明不确定，并告诉用户如何补拍。

参考公开表述：

- [2016 微信公开课：微信四个价值观](https://meia.me/course/168417)
- [2018 微信公开课：“用完即走”的本质是高效完成任务](https://tech.sina.cn/i/gn/2018-01-15/detail-ifyqrewi2341559.d.html)
- [2019 微信公开课：产品需要内在一致](https://cloud.tencent.com/developer/article/1989962)

## 3. 当前体验诊断

### 3.1 首页主次倒置

当前首页先展示“最常见的蘑菇”，拍照识别入口位于列表之后。用户需要先穿过内容，再找到主任务。

调整：

- 拍照识别成为首屏唯一主视觉。
- 常见蘑菇缩减为轻量入口，不在首页展开长列表。

### 3.2 识别过程压过识别结论

当前识别页默认展开流式思考，技术过程占据主要空间。用户真正关心的是“可能是什么、危险吗、为什么这样判断”。

调整：

- 识别中只显示简洁状态和可感知进度。
- 结果先展示候选与安全提示。
- “识别依据”默认收起，内容只包括图片中可观察的特征，不展示模型内部推理。

### 3.3 视觉强调过多

当前大面积森林绿 TopAppBar、多个彩色容器与卡片同时出现，页面容易显得沉重。

调整：

- App 主背景改为安静的暖灰白。
- 顶栏使用同色背景，仅标题和图标建立层级。
- 品牌绿只用于主按钮、选中态和少量关键强调。

### 3.4 图鉴筛选拥挤

五个固定 Tab 在窄屏上密度较高，且“可食”“有毒”容易让用户把分类当作确定结论。

调整：

- 搜索优先。
- 筛选改为可横向滚动的筛选 Chip。
- 使用“有食用记录”“毒性风险”“需谨慎”等更严谨文案。

### 3.5 页面结构不够统一

首页、图鉴、详情、识别和个人页分别使用不同的标题栏、卡片与间距逻辑。

调整：

- 建立统一页面骨架、间距、圆角、按钮和信息分组规范。
- 让不同页面看起来属于同一件工具，而不是多个功能 Demo 的集合。

## 4. 新信息架构

底部导航保留三个入口，但重新命名与排序：

1. **识别**
2. **图鉴**
3. **我的**

“识别”既是首页，也是默认启动后的主页面。

```text
识别
├── 相机
├── 照片确认
├── 识别中
└── 识别结果
    ├── 候选详情
    └── 3D 查看

图鉴
├── 搜索与筛选
└── 物种详情

我的
├── 收藏
├── 设置
├── 免责声明
└── 关于
```

首次启动保留引导，但由三页缩减为一页说明和一次确认。

## 5. 核心用户流程

### 5.1 首次使用

```text
启动页 → 单页安全说明 → 进入识别首页
```

原则：

- 不用三页轮播教育用户。
- 只解释产品能做什么、不能做什么、照片如何处理。
- 用户确认免责声明后进入产品。

### 5.2 拍照识别

```text
识别首页 → 相机 → 照片确认 → 识别中 → 识别结果
```

目标：

- 首页到相机：1 次点击。
- 拍照到提交：1 次点击。
- 结果页优先回答“是什么”和“是否存在风险”。

### 5.3 图鉴查阅

```text
图鉴 → 搜索/筛选 → 物种详情 → 收藏或返回
```

目标：

- 搜索始终比分类更突出。
- 列表项展示识别所需信息，不堆叠季节、栖息地、用途等所有字段。

## 6. 页面设计

### 6.1 启动页

内容：

- 中心放置单色蘑菇标志。
- 下方仅显示产品名“识菇”或现有正式名称。
- 初始化时使用细线进度，不显示多段宣传语。

视觉：

- 暖灰白背景。
- 标志使用深墨绿。
- 不使用渐变、插画轮播和口号动画。

动效：

- 180ms 淡入。
- 数据完成后自然切换，不设置人为等待时间。

### 6.2 首次安全说明

页面只保留：

- 标题：“先说清楚一件事”
- 正文：“照片识别只能提供候选，不能作为采食或医疗依据。”
- 两条补充：如何拍清楚、图片如何使用。
- 勾选：“我已阅读并理解上述说明。”
- 主按钮：“开始使用”

“隐私政策”和“免责声明”使用正文链接，不与主按钮争夺视觉。

### 6.3 识别首页

页面结构：

```text
┌──────────────────────────┐
│ 识别                 记录 │
│                          │
│      [安静的蘑菇轮廓]      │
│                          │
│   拍下你看到的蘑菇         │
│   尽量包含菌盖、菌褶和菌柄  │
│                          │
│   [       拍照识别       ] │
│        从相册选择           │
│                          │
│ ──────────────────────── │
│ 不确定是否安全？不要采食    │
└──────────────────────────┘
```

设计要求：

- 主按钮进入首屏下半部，单手可达。
- 页面不展示常见蘑菇长列表。
- “记录”仅在存在识别历史时出现；没有记录时不展示空入口。
- 安全提示为普通文本，不使用持续警报式红色横幅。

首页的“常见蘑菇”移动到图鉴首页，可保留一个低强调文字入口：“浏览常见蘑菇”。

### 6.4 相机页

页面结构：

- 全屏真实取景画面。
- 左上角关闭。
- 右上角仅保留可用的闪光灯控制。
- 中央使用四角取景框，不盖住主体。
- 底部显示一句动态拍摄建议。
- 快门为 72dp 白色圆形按钮。
- 相册入口位于快门左侧或下方，保持明确但次要。

拍摄建议按顺序轮换：

- “让整株蘑菇进入画面”
- “再靠近一点，拍清菌褶”
- “避免手或树叶遮挡菌柄”

不显示当前尚未实现的前后摄像头切换或伪闪光按钮。

### 6.5 照片确认页

页面结构：

- 图片尽可能占满可用区域。
- 顶部返回行为直接表示“重拍”。
- 底部固定操作区：
  - 次按钮：“重拍”
  - 主按钮：“使用这张”

照片质量提示：

- 正常时不显示警告。
- 只有确实检测到模糊、过暗或尺寸过小时才显示。
- 提示说明问题和修正方式，不使用泛化的固定警告。

### 6.6 识别中

页面结构：

```text
[照片缩略图]

正在识别
已看到菌盖和菌柄，正在匹配候选…

[轻量进度动画]

这通常需要几秒

[取消]
```

要求：

- 不滚动展示模型 token。
- 不显示“思考过程”。
- 状态文案来自可解释的处理阶段，而不是伪造精确进度。
- 超过合理时间后再出现“网络较慢，可以继续等待或取消”。

### 6.7 识别结果

信息优先级：

1. 安全边界。
2. 最可能候选。
3. 其他候选。
4. 识别依据。
5. 下一步操作。

页面结构：

```text
┌──────────────────────────┐
│ 识别结果              完成 │
│                          │
│ 无法确认是否可食           │
│ 仅凭照片不能排除有毒近似种  │
│                          │
│ 最可能                    │
│ [图片] 灰花纹鹅膏          │
│        Amanita ...        │
│        与照片较为相似       │
│                          │
│ 其他可能                  │
│ 1. ...                    │
│ 2. ...                    │
│                          │
│ > 为什么这样判断           │
│                          │
│ [查看详细资料]             │
│ 重新拍照                   │
└──────────────────────────┘
```

关键规则：

- 不把模型置信度百分比作为权威数字突出展示。
- 使用“较为相似 / 有一定可能 / 信息不足”这类校准文案。
- 毒性结论优先使用“风险”表达，不用绿色“可安全食用”。
- “为什么这样判断”展开后只显示可观察依据，例如菌盖颜色、菌环、菌托、生境。
- 原始模型输出仅用于调试日志，不进入用户界面。
- 3D 是探索性次级功能，放在详细资料页，不与结果页主操作并列。

### 6.8 图鉴列表

页面结构：

- 顶部标题“图鉴”，不使用实色大顶栏。
- 搜索框紧随标题，支持中文名和学名。
- 筛选 Chip 横向滚动：
  - 全部
  - 有食用记录
  - 药用记录
  - 毒性风险
  - 需谨慎
- 下方显示结果数量和列表。

列表项：

- 64dp 图片。
- 中文名为主标题。
- 拉丁学名为辅助文本。
- 仅展示一个风险标签和一个生境摘要。
- 整行可点击，右侧不额外堆叠箭头、按钮和图标。

### 6.9 物种详情

首屏结构：

- 大图。
- 中文名、拉丁学名。
- 风险标签。
- 一句话摘要。

正文按自然阅读顺序：

1. 如何辨认。
2. 易混淆种。
3. 生境与季节。
4. 毒性与症状。
5. 数据来源。

交互：

- 收藏使用顶栏图标，不出现额外大按钮。
- 有 3D 数据时，在“观察结构”分组中提供入口。
- 来源链接明确标识外部网站。
- 免责声明放在风险信息附近，不藏在页面最底部。

### 6.10 我的

页面不做个人主页包装，不放头像占位、等级或统计。

分组：

- 我的收藏
- 偏好设置
- 隐私与免责声明
- 关于

使用原生设置列表样式，图标只在确有辨识价值时出现。

## 7. 视觉系统

### 7.1 美学方向

关键词：

- 安静
- 可信
- 自然
- 清醒
- 不卖弄

拒绝：

- 森林主题装饰泛滥
- 大面积深绿色顶栏
- 过多圆角卡片
- Emoji 作为正式状态图标
- 渐变、玻璃拟态、高阴影
- 用绿色暗示“可以吃”

### 7.2 色彩

浅色模式：

| Token | 色值 | 用途 |
|---|---:|---|
| `background` | `#F7F7F5` | 页面背景 |
| `surface` | `#FFFFFF` | 浮层、输入区 |
| `textPrimary` | `#1F2421` | 主文字 |
| `textSecondary` | `#6F7671` | 次文字 |
| `brand` | `#2F6B4F` | 主按钮、选中态 |
| `brandPressed` | `#25563F` | 按压态 |
| `divider` | `#E5E8E5` | 分隔线 |
| `riskHigh` | `#B34237` | 高风险 |
| `riskMedium` | `#A66A1F` | 需谨慎 |
| `info` | `#3F657A` | 中性信息 |

规则：

- 单屏除中性色外，最多出现两个强调色。
- 风险必须同时用文字和图标表达。
- “无已知毒性记录”使用中性信息色，不使用成功绿。

深色模式：

- 保持接近系统深灰，不使用纯黑。
- 品牌色降低饱和度，避免荧光感。
- 图片和风险信息的对比度优先。

### 7.3 字体

使用系统字体，减少包体与渲染差异：

- 中文：Android 系统无衬线。
- 拉丁学名：系统字体斜体。
- 数字和百分比不使用特殊展示字体。

字号：

| 层级 | 字号 | 字重 |
|---|---:|---|
| 页面标题 | 28sp | Medium |
| 结果标题 | 24sp | Medium |
| 分组标题 | 18sp | Medium |
| 正文 | 16sp | Normal |
| 辅助文本 | 14sp | Normal |
| 标签 | 12sp | Medium |

规则：

- 少用粗体。
- 不用全大写英文标签。
- 正文行高不低于字号的 1.45 倍。

### 7.4 间距

采用 4dp 基础网格：

- 页面水平边距：20dp。
- 紧密内容间距：8dp。
- 相关内容间距：12dp。
- 分组间距：24dp。
- 大区块间距：32dp。
- 底部安全区额外留白：16dp。

### 7.5 圆角与阴影

- 主按钮：12dp。
- 输入框：12dp。
- 图片：12dp。
- 信息容器：12dp。
- 标签：6dp。
- 默认不使用阴影，以背景、留白和 1dp 分隔线建立层级。
- 只有底部固定操作区和临时浮层允许低强度阴影。

## 8. 组件规范

### 8.1 主按钮

- 每屏最多一个。
- 高度 52dp。
- 满宽或接近满宽。
- 文案使用动词，例如“拍照识别”“使用这张”“查看详细资料”。

### 8.2 次按钮

- 文字按钮或描边按钮。
- 不与主按钮使用相同填充色。
- “重拍”“取消”“完成”等退出性操作使用次级样式。

### 8.3 风险提示

三层：

- 高风险：明确有毒或存在致命近似种。
- 需谨慎：信息不足、近似种较多。
- 中性信息：没有可靠食用结论。

所有层级都必须显示：

- 图标
- 风险标题
- 一句可执行建议

### 8.4 物种列表项

- 使用平面列表，不默认包在独立卡片中。
- 行间使用留白或分隔线。
- 图片、名称、风险三者足以形成扫描路径。

### 8.5 展开区

用于：

- 识别依据
- 数据来源
- 完整免责声明

默认收起，标题必须说明展开后能看到什么，不能使用模糊的“更多”。

## 9. 动效与反馈

原则：

- 动效解释状态，不装饰等待。
- 单次动效一般控制在 120-240ms。
- 尊重系统“减少动态效果”设置。

具体：

- 页面进入：轻微淡入，不做横向大位移。
- 展开识别依据：高度与透明度过渡，180ms。
- 按钮按压：颜色加深和 0.98 缩放，80ms。
- 识别中：使用低频呼吸点或细线循环，不使用旋转蘑菇。
- 结果出现：整体淡入，不逐卡片弹跳。

## 10. 文案原则

### 10.1 像朋友一样说清楚

使用：

- “这张照片更像……”
- “仅凭照片还不能确认。”
- “再拍一张菌褶和菌柄，会更容易判断。”
- “不要根据本结果采食野生蘑菇。”

避免：

- “AI 正在深度思考”
- “权威识别”
- “准确率 99%”
- “放心食用”
- “识别失败”

将“识别失败”改为具体原因：

- “照片太暗，暂时看不清关键特征。”
- “候选之间太相似，需要更多角度。”
- “当前网络不可用，可以稍后重试。”

### 10.2 技术退后一步

- 首页不强调 MiniMax、模型版本或 AI。
- 用户需要的是识别服务，不是模型演示。
- 模型和数据来源放在“关于”和结果来源信息中。

## 11. 可用性与无障碍

- 所有触控区域至少 48×48dp。
- 正文与背景对比度达到 WCAG AA。
- 状态不只依赖颜色。
- TalkBack 顺序与视觉顺序一致。
- 图片提供物种名或功能性描述。
- 相机按钮、关闭、闪光灯和相册入口都有明确 content description。
- 支持系统字体放大到 1.3 倍时不截断主要操作。
- 底部按钮避开手势导航区域。

## 12. 数据与隐私体验

- 首次使用说明照片是否上传、用于什么、保存多久。
- 相机权限在用户点击拍照后再申请，不在启动时索取。
- 相册权限只在用户选择相册时触发。
- 识别记录默认仅本地保存；若当前实现并非如此，需要在开发前重新确认。
- 设置中提供“清除识别记录”和“清除图片缓存”。

## 14. 验收标准

### 任务效率

- 冷启动完成后，用户 1 次点击可进入相机。
- 拍照后，1 次点击可开始识别。
- 识别结果首屏可以看见最可能候选和安全边界。

### 视觉一致性

- 主页面不再使用大面积实色 TopAppBar。
- 每屏最多一个主按钮。
- 列表、按钮、输入框、风险提示遵循统一组件规范。
- 单屏强调色不超过两个。

### 信息可信度

- 不显示原始模型思考过程。
- 不将置信度百分比包装为准确率。
- 不出现“放心食用”等承诺性文案。
- 所有识别结果都带有不可作为采食依据的提醒。

### 可访问性

- 关键触控区域不小于 48dp。
- 风险状态具备图标和文本双重表达。
- 大字体下主流程无内容遮挡。
