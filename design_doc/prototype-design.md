## 0. 设计原则(Design Principles)

| 原则 | 解释 |
|---|---|
| **专家背书,不是 AI 炫技** | 视觉上要让"你(专家)"在背后,不是"算法"在前。结论页要让人看到真人头像 + 资质 |
| **30 分钟 SLA 看得见** | 倒计时、状态通知要清晰,让用户知道"我的照片正在被看" |
| **安全优先于好看** | 颜色不用红绿对比(色弱友好),危险信号用图标+文字双通道 |
| **离线优先** | 山上没信号时,100 种图鉴必须能浏览;网络图标常驻 |
| **截图友好** | 用户大概率会把 App 截图发群拉新,设计要让"订单页"、"结果页"看起来像一张有说服力的卡片 |

## 1. 视觉令牌(Design Tokens)

### 1.1 色板(Material 3 派生,蘑菇主题)

| Token | Hex | 用途 |
|---|---|---|
| `primary` | `#2E5D3A` (森林绿) | 主操作按钮、顶部 App Bar |
| `onPrimary` | `#FFFFFF` | 主按钮文字 |
| `primaryContainer` | `#B7E4C7` | 选中态、强调背景 |
| `secondary` | `#8B5A2B` (土褐色) | 副按钮、辅助色 |
| `tertiary` | `#D4A574` (蘑菇色) | 装饰、卡片底色 |
| `surface` | `#FAF8F3` (米白) | 背景 |
| `error` | `#B3261E` (暗红) | 错误、危险信号(**不**用纯红) |
| `warning` | `#E8A33D` (琥珀) | 待处理、中间态 |
| `success` | `#3D8B5A` (草绿) | 成功、已鉴别 |
| `onSurface` | `#1B1B1B` (近黑) | 正文 |
| `outline` | `#CFCFCF` (浅灰) | 分割线、边框 |

**禁忌:**
- 不用纯红 `#FF0000` / 纯绿 `#00FF00`(色弱不友好 + 廉价感)
- 不用超过 5 种颜色同时出现在一个屏幕

### 1.2 字体

- **主字体:** 系统默认中文(Android 上即 Source Han Sans / Noto Sans CJK SC)
- **西文:** Roboto
- **比例:** Material 3 默认(Display 57/45/36, Headline 32/28/24, Title 22/16, Body 16/14, Label 14/12)
- **特殊:** 蘑菇学名用斜体 + 灰色(科学引用感)

### 1.3 间距 / 圆角

- 基础间距: 4dp 网格(4/8/12/16/24/32)
- 卡片圆角: 12dp
- 按钮圆角: 8dp
- 输入框圆角: 4dp(避免抢眼)
- 阴影: elevation 1dp(轻,不用 Material 3 那种高阴影)

### 1.4 图标

- Material Symbols Rounded(系统默认)
- 自定义:**蘑菇图标**(用于 App 图标、Tab Bar 的"图鉴"入口、Loading 状态)
- 状态图标: ✅ ✔ ⏰ ⚠️ 🚨(Material Symbols 都覆盖)

## 2. 屏幕清单(MVP 12 屏)

| # | 屏幕 | 核心目的 | 何时进入 |
|---|---|---|---|
| S1 | 启动页 (Splash) | 启动 + 初始化 | App 冷启动 |
| S2 | 首次启动引导 (Onboarding) | 免责声明 + App 介绍 | 首次安装 |
| S3 | 首页 (Home) | 一目了然:我的订单 + 进入鉴别/图鉴 | 登录后/订单后回主 |
| S4 | 拍照 (Camera) | 取景框 + 拍照按钮 | Home → "立即鉴别" |
| S5 | 照片预览 (PhotoPreview) | 确认 + 重拍 | S4 拍照后 |
| S6 | 特征填表 (FeatureForm) | 填关键特征(必填) | S5 确认后 |
| S7 | 订单确认 + 支付 (Paywall) | 显示价格 + SLA + 支付按钮 | S6 提交后 |
| S8 | 等待中 (Waiting) | 30 分钟倒计时 + 状态 | 支付成功 → 等待结论 |
| S9 | 结论 (Result) | 专家结论 + 配图 + 风险 | 推送收到 → 点开 |
| S10 | 历史 (History) | 全部订单 | Home → "我的订单" |
| S11 | 图鉴浏览 (SpeciesList) | 100 种蘑菇列表 | Home → "图鉴" |
| S12 | 图鉴详情 (SpeciesDetail) | 单种蘑菇全信息 | S11 点某条 |
| S13 | 个人中心 (Profile) | 设置/客服/法务 | 顶部 App Bar 头像 |

**总 13 屏,核心 7 屏(S3-S9),辅助 6 屏。**

## 3. 屏幕详解(ASCII 草图)

### S1. 启动页 (Splash)

```
┌─────────────────────────────┐
│                             │
│                             │
│         🍄                  │
│      [蘑菇图标]              │
│                             │
│      蘑菇鉴别                │
│   Mushroom ID                │
│                             │
│                             │
│  ●○○  加载本地数据...         │
│                             │
└─────────────────────────────┘
```

- **目的:** 启动时把 100 种 seed JSON 导入 Room,完成后跳转 S2 或 S3
- **时长:** 首次 1-2 秒(导入),后续 0.5 秒闪一下就走
- **异常:** 导入失败 → 弹 Toast 提示"数据加载失败,请重试"


3 步分别讲: ① 真人专家,30 分钟 SLA ② AI 预筛辅助 + 100 种本地图鉴 ③ 出错包赔 + 免责声明

- **不勾选无法进入 S3**
- 用户协议 / 隐私政策 / 免责声明 在设置页可重看

- **错误:** 模糊/曝光异常 → 拍照后弹"建议重拍"提示(不强制)

- **结果分 4 类,视觉区分:**

  - 可食(常见食用菌): 绿色横幅 + ✅
- **"再看一次"按钮:** 用户复购入口
- **"截图发给朋友"按钮:** 一键系统分享,带动传播
- **"申请复核"按钮:** 免费二次专家审(留 24 小时内有效),消除"万一错了"的担忧

## 7. 边界情况(Edge Cases)

| 情况 | 设计 |
|---|---|
| 100 种图鉴都没有命中 | S6 提交时弹"您填的特征较少匹配,可能需要多张图,建议补充菌褶特写" |
| 用户填了"无"菌环菌托 | 评分降低,候选可能跳到无环无托的种(草菇、红菇等),结论文案要明确"无环无托不等于无毒" |
| 照片极小(<50KB) | 拍照后提示"图片过小,可能影响识别" |
| 照片极暗 | 提示"光线不足"建议重拍(检测平均亮度) |
| 用户 5 分钟内重复下单 | 提示"你有一个订单正在进行中,是否继续提交新的?" |
| 用户无障碍(色弱/视障) | 全部状态用图标+文字双通道,不用单一颜色编码 |
| 网络从断到恢复(等待中) | S8 倒计时恢复,自动重连推送 |
| 跨时区/手机时间被改 | 用服务端时间戳,不用本地时间 |

### 10.4 3D 数据集机会(2026-06-08 重大新闻)

> **重要发现:** 中国西南地区大型真菌资源数据库 + 云南野生菌子实体三维形态数据库 2026-06-08 上线。

**关键数据(人民日报报道):**
- **总数据规模:** 8648 条真菌物种/标本 + 28000+ 张子实体照片 + 8648 条 DNA 序列
- **3D 数据库:** 423 个大型真菌子实体的三维图像,覆盖 66 科 182 种**常见**大型真菌
- **建设方:** 中国科学院昆明植物研究所
- **战略地位:** 物种分类、鉴定、识别 + 真菌资源普查、保护、评估

**对 App 的影响:**

| 之前认知 | 现在现实 |
|---|---|
| "调 iflora 3D 数据做对比,大概率 work 不了" | **如果这 423 种的 3D 模型对公众开放,你 App 可以直接调,而不是 2D → 3D 比对** |
| "3D 是 Phase 2,YAGNI" | **3D 是 iflora 官方数据,直接展示即可,不用自己做 3D 扫描** |
| "MVP 100 种 + 离线图鉴" | **100 种里 80 种可能就在 iflora 3D 的 182 常见种里** |

**Phase 2 重新评估建议:**

1. **直接调 iflora 3D 模型 URL,在 App 内嵌 viewer 展示**(不调 3D 比对,只展示)
2. **MVP 100 种**优先选 iflora 3D 数据库覆盖的 182 种,这样每个种都有 3D 资源
3. **联系中科院昆明植物所**,谈 API 接入(可能需要授权)

**风险:**
- iflora 3D 模型可能**不公开 API**,只在前端展示。这种情况只能 webview 嵌入或截图
- **版权:** 中科院数据可能有使用限制,商业用途需授权
- **3D viewer 选型:** SceneView(开源)vs Filament(更轻量)vs WebView + three.js(最简)

### 10.5 关键洞察:MVP 100 种 vs iflora 8648 种

| 维度 | iflora 全量 | MVP 100 种 | 关系 |
|---|---|---|---|
| 物种范围 | 西南地区(云南为主) | 全国(你的 1000 群覆盖) | **MVP 更广,需补 iflora 之外的种** |
| 字段完整度 | 23 个字段全填 | 你只需填 13 个 MVP 必填 | **MVP 工作量 = 100 × 13 = 1300 个字段,手工约 10-20 小时** |
| 图片质量 | 28000+ 张,大多有 CC 协议 | 300-500 张,**版权需自审** | **MVP 必须每个种 3-5 张** |
| 3D 模型 | 423 种有 | MVP 不需要 | **Phase 2 用 iflora 的,不重做** |
| DNA 条形码 | 8648 条 | MVP 不展示 | Phase 2 加 |
| 分布数据 | 完整 | MVP 不展示 | Phase 2 加 |

**给你的判断:**
- **不要爬 iflora 全量** — 不是技术不能,是(1) MVP 用不到,(2) 版权/协议可能不允许,(3) 1300 个字段手工填比爬 8648 条再清洗要快且准
- **手挑 100 种后,ifora 那 100 个 source_url 留着**,以后做"详细信息跳转"用
- **如果 100 种里有 > 50 种在 iflora 3D 的 182 种里**,Phase 2 直接调 iflora 3D 即可,省 100 倍工作量

5. **暗色模式:** S13 有"深色模式"开关。MVP 跟随系统,还是给用户手动开关? 暗色蘑菇图鉴的对比度问题要提前考虑。
6. **S6 填表是不是太长了?** 4 个必填 + 2 选填,采菇人在山上冻手填。考虑改为"先拍照 → 提交后引导补填"?
